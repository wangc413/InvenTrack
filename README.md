# 发货助手

仓库发货用的手机端工具。**按拖板记录**：一板一品，一边看着 3D 一边码，码完这块装上车，自动跳到下一块。

纯网页应用（PWA），不装 App、不进应用商店。手机浏览器打开即用，可添加到主屏幕。

## 能做什么

- **建车次只定两件事**：送到哪、发给谁。装什么进场再说，不用事先算好要几板
- **收货地会记着**：最近发过的几家列在下面，下次点一下就填上
- **建完直接进 3D 装板**：不用再点一层，落地就是一块空托盘等你放货
- **一屏就是一块板**：3D 占满整屏，层数、顶层直接在画面上的那条卡片里按 + −，品和日期收在两个下拉里
- **一板一装**：点「装上 P3」，这块定下来，界面直接跳成 P4 的空板，接着码下一块
- **一层怎么摆是写死的**：1.2 × 1.0 米标准托盘，包子一层 7 个（3 竖 + 4 横，横的 4 个挤成 2×2），
  烧麦一层 5 个（后排 3 竖 + 前排 2 横，前排两个居中、中间留约 9 cm 窄缝）；**隔层整体调头 180°**，上下缝错开压住，垛才不歪
- **库存也按箱**：入库、退货、盘点都填箱数，零头件单列一格，结存一眼看箱
- **一板一品**：一块拖板只放一种商品、一个生产日期，混装查不了账
- **生产日期必选**：日期来自实际入库记录，库存里没有的日期选不了，避免发错批次
- **3D 装车预览**：快乐猴五个品直接用外箱设计稿贴图，箱面就是印出来的样子；拖一下就能转着看这板货堆出来什么样
- **发车记录**：发过的车都留档，点开仍可回看 3D，也能撤销
- **库存流水**：入库、发车、退货、盘点都记成流水，结存由流水实时算出，随时能查账
- **撤销发车**：发错了撤回，库存按原批次回补，单据退回未发车可以改完再发
- **库存不足直接拦**：这一板码出来的箱数超过这个日期还剩的，数字标红、「装上」按钮变灰，
  发车前还会再核一遍，不会把账记成负数
- **导出**：发货明细导 CSV，Excel 直接打开

## 库存是怎么算的

**不存“当前库存”这个数字，只存流水。** 每一笔入库、发车、退货、盘点都记一条带正负号的流水，
结存 = 所有流水相加。这样任何一个环节变动，库存会自动跟着变，不会出现两处数字对不上。

| 动作 | 记成什么流水 | 库存变化 |
|---|---|---|
| 入库 | `+箱数 × 每箱件数` | 增加 |
| 发车 | `-箱数 × 每箱件数`，按批次先进先出拆开记 | 减少 |
| 退货 | 同上，回到原批次 | 增加 |
| 盘点 | `(实盘 - 账面)`，正负都可能 | 校正 |
| 撤销发车 | 把当初的出库逐条反向记回 | 还原 |

**看得见的单位是箱，账本里存的是件。** 入库、退货、盘点都按箱填，零头件单独填一格；
界面上一律先给箱数，件数当第二行小字跟着。账本内部仍按件记，是因为件是跟客户对账的最小单位，
万一有一箱拆开零卖也不会算错。

「库存」页点开任意品项，能看到结存多少箱、每个批次剩多少箱、以及最近几条流水，账是怎么来的全在这儿。

库存不够就发不出去。码好这一板，箱数超过「这个日期还剩多少箱」时，3D 左下角那行字变红、
写明还能装几箱，「装上」按钮同时变灰；车次里已经占用的箱数也会算进去（同车码第二块同品同日期的板时，
按剩下的额度算）。发车前还会再核一遍，不够就弹错拦住，不会把账做成负数。
确实要先发货后补单，就先入库把这个日期的货记上，或者把层数减下来。

**示例库存**：盒马三个品（肉包 / 菜包 / 烧麦）每个生产日期各 200 箱、四个日期；
快乐猴五个品（肉包 / 菜包 / 菜团子 / 饺子 / 糯米鸡）每个日期各 100 箱、两个日期。
菜洋洋只留了 10 箱，用来试「库存不足」的拦截。
老数据升级时按版本号补：v2 补盒马、v3 补快乐猴的五个品项和库存，只补差额，不动已有单据。

## 一次完整的装车流程

1. 「装车」→「新建车次」→ 填**收货地**（最近用过的点一下就能填）→ 选**收货方**
2. 点「创建并开始装板」，**直接进 3D 装板页**，面前是一块空托盘
3. 选**装什么**（这一家名下的品）→ 选**生产日期**（只列有库存的）
4. 品和日期在顶部两个下拉里切换；**层数、顶层几个**在 3D 底部那张卡片上按 + −，3D 实时跟着变，
   同一张卡片上显示这一板多少箱、这天还剩多少箱
5. 「装上 P1」→ 这块定下来，界面自动跳成 **P2 的空板**，接着码下一块
6. 想看看整车什么样，点左上返回，页面上能看到已上车几板、合计多少箱多少方
7. 全码完「确认发车」

**多少板不是你填的，是你码出来的。** 库里拉出来的一板可能只有 5 层、顶层还缺两个角，
这些都能在 3D 里点出来，不用事先算总数：

| 参数 | 怎么定 |
|---|---|
| 每层几个 | **现场写死的码法**：包子 7 个（3 竖 + 4 横，横的 4 个挤成 2×2），烧麦 5 个（后排 3 竖 + 前排 2 横，前排居中、中间留约 9 cm 缝）。只显示，不给调 |
| 隔层调头 | 单数层整体转 180°，上下层的缝错开压住，和现场码法一致 |
| 层数 | 按连托盘 1.8 米高倒推，肉包 8 层、烧麦 7 层，可自己加可自己减 |
| 最上层几个 | 默认跟每层一样；顶层没码满就往下减，3D 里会按码放顺序留出缺角 |

层数超过 1.8 米不会拦你，只是左下角那行字变红提醒「注意车厢高度」。
一层摆法是写死的：箱子怎么转、摆在哪，都是现场量出来的固定排法，不是程序现算的最大值。

发完之后在「记录」里能翻到这一车，点开还是那张 3D 图，也能撤销。

## 3D 是怎么来的

箱子不是通用方块，是照着实拍外箱做的：

| 品 | 外径 长×宽×高 | 一层几个 | 箱面 |
|---|---|---|---|
| 盒马 鲜汁大肉包 | 500×335×190 mm | 7（3 竖 + 4 横） | **外箱设计稿** |
| 盒马 翡翠香菇青菜包 | 500×340×200 mm | 7（3 竖 + 4 横） | **外箱设计稿** |
| 盒马 纸皮烧麦 | 465×410×235 mm | 5（3 竖 + 2 横留缝） | **外箱设计稿** |
| 快乐猴 鲜汁大肉包 | 500×340×220 mm | 7（3 竖 + 4 横） | **外箱设计稿** |
| 快乐猴 翡翠香菇大菜包 | 500×340×220 mm | 7（3 竖 + 4 横） | **外箱设计稿** |
| 快乐猴 菜团子 | 445×350×270 mm | 8（2 + 3 + 3） | **外箱设计稿** |
| 快乐猴 水饺 | 430×300×230 mm | 10（6 竖 2×3 + 4 横一列） | **外箱设计稿** |
| 快乐猴 荷香糯米鸡 | 400×345×235 mm | 7（3 竖 + 4 横） | **外箱设计稿** |

**盒马三个、快乐猴五个，八个品都是照刀版稿真贴的。** 从外箱 PDF 里按刀版边界裁出三张：正面（长×高）、
侧面（宽×高）、顶面（前后两个摇盖各占一半，后摇盖转 180° 拼上去，跟真箱合盖后一样）。设计稿里的品名、logo、
配料表、条码、贮运图标全都在，箱子码起来就是印出来的样子。贴图在 `src/assets/pack/`（WebP，24 张约 720 KB）。

自己新建的品没有稿子，就现画一套：正面是牛皮底 + 底部品牌色带 + 品名大字 + 规格，
侧面是缩小的品名 + 配料表小字 + 条码，顶面是两块摇盖合上的中缝加「此面朝上」，
配色跟着档案里填的品牌色走，不再是一块纯色 + 一个标题。

拖板按 1200×1000 mm 标准板建模，
包含面板和三层垫块，箱子按每个品的固定码法摆，转 90° 的那几个会跟着转，
单数层整层再调头 180°，所以能看出砖块那样交错咬合。
饺子 10 箱、菜团子 8 箱这两层按真实箱规是摆不进 1.2×1.0 的，
现场是把箱子堆到板沿外，所以 3D 也照实画，操作卡上那行字变红写明探出多少
（饺子左右各 4.5 cm、前后各 1.5 cm，菜团子各 12 cm）。
装好之后的板卡片一行品名绑定生产日期，口算式写齐全：「6 层 × 7 个 + 顶层 5 个 = 47 箱」，总数加粗放在中间；
右下角重码 / 移除收成两个 40px 的图标按钮，都要点两下才执行（第一下变红出「确认」，2.6 秒不点就自己退回去）。
相机按整垛（含托盘）的包围盒在当前视角下的投影取景，换手机、转屏幕都不会切到货。

**改箱规**：档案页点开任意品，填外径长宽高（毫米）和箱面颜色，3D 会立刻按新尺寸重算。

**看 3D 要下载 127 KB 的模型库 + 约 720 KB 箱面贴图**，只在第一次点 3D 时加载，不影响首屏速度，之后走浏览器缓存。

## 本地运行

```bash
npm install
npm run dev
```

浏览器打开终端提示的地址（通常是 http://localhost:5173）。

## 部署到 GitHub Pages（获取一个固定网址）

### 1. 在 GitHub 上新建仓库

打开 https://github.com/new ，仓库名随便填（例如 `ship-helper`），
**必须选 Public**，不要勾选任何初始化文件，点 Create repository。

### 2. 把代码推上去

在本目录下执行（把 `你的用户名` 和 `ship-helper` 换成你的）：

```bash
git branch -M main
git remote add origin https://github.com/你的用户名/ship-helper.git
git push -u origin main
```

### 3. 打开 Pages

仓库页 → **Settings** → 左侧 **Pages** → 找到 **Build and deployment**，
把 **Source** 改成 **GitHub Actions**。

### 4. 等自动构建

仓库页 → **Actions** 标签，会看到 `Deploy to GitHub Pages` 正在跑，等它变绿（约 1 分钟）。

### 5. 拿到网址

地址是：

```
https://你的用户名.github.io/ship-helper/
```

这个地址**永久不变**。以后改了功能，只要 push 一次，刷新就是新版，网址和二维码都不用换。

### 6. 生成二维码

打开 App 的「我的」页面，二维码已经生成好了，截图保存或直接打印，贴在仓库门口和工位上。

## 手机上用起来像 App

- **安卓 Chrome**：打开网址 → 右上角菜单 → 添加到主屏幕
- **iPhone Safari**：打开网址 → 底部分享按钮 → 添加到主屏幕

添加后从桌面图标进入，是全屏的，没有浏览器地址栏。

## 界面

按 iOS 原生的样子做：大标题、分组列表、发丝分隔线、半透明模糊的底部标签栏，没有阴影和描边，
数字统一用等宽字形。整体是黑白灰，只有两类地方带颜色：超发、超载用红，出货和库存增加用绿，
其余一律不给颜色。

底部五个页签：**装车 · 记录 · 库存 · 档案 · 我的**。

想直接把某一页发给同事，可以在网址后面加 `?tab=`：

| 参数 | 打开 |
|---|---|
| `?tab=ship` | 装车（默认） |
| `?tab=records` | 记录 |
| `?tab=stock` | 库存 |
| `?tab=catalog` | 档案 |
| `?tab=me` | 我的 |

老链接 `?tab=pallet` / `?tab=load` 会跳到装车，`?tab=record` 会跳到记录。

### 换图标

图标在 `public/` 下，四个文件各管一处：

| 文件 | 用在哪 |
|---|---|
| `favicon.svg` | 浏览器标签页、书签（矢量，任意缩放不糊） |
| `icon-192.png` | 安卓主屏幕 |
| `icon-512.png` | 安卓主屏幕 / 应用列表 |
| `apple-touch-icon.png` | iPhone 主屏幕（180×180） |

换成自己的图：正方形、边长至少 512px，图案主体放在中间 70% 以内（四周会被系统裁成圆角）。
替换同名文件即可，`manifest.webmanifest` 不用动。

**换了图标之后，已经添加到主屏幕的旧图标不会自己变**——iOS 和安卓都会缓存。
要把那个图标删掉，重新用浏览器打开网页、重新「添加到主屏幕」，才会显示新的。

## 数据说明

**数据存在你自己的手机浏览器里（IndexedDB 浏览器数据库），不会上传到任何服务器。**

- 你和同事各自扫码打开，是各自独立的一份数据，互相看不到，也不会实时同步
- 换手机、清缓存、换浏览器都会读不到旧数据
- 重要数据请定期在「我的 → 导出备份」存一份 JSON

**如果两个人要同时录同一车货，这个版本不能用**——两个人各算各的，库存一定会对不上。
需要多人共享时，要额外接一个云数据库，界面不用改。

### 能存多少条

一车 8 块拖板约 1.3 KB（含品项、生产日期、层数、时间），实际占用按手机剩余空间分配：

| 记录量 | 占用 | 说明 |
|---|---|---|
| 100 车 | 约 130 KB | 一个月都用不到 |
| 1,000 车 | 约 1.3 MB | 一年多的量 |
| 10,000 车 | 约 13 MB | 十年量，手机照样无压力 |

早期版本用的是 localStorage（上限 5 MB，约 2,000 车就满），现在换成 IndexedDB，
上限变成手机剩余空间的一部分（通常几百 MB 起），并且启动时会自动把老数据搬过去。

「我的 → 容量」可以看到实时占用、已记车次，以及按剩余空间还能记多少车。
写入失败时页面顶部会直接弹红条提示，不会再出现「显示成功但其实没存下来」的情况。

## 常见问题

**客户和品项以后要加怎么办？**
档案页最下面是「客户」，点「新增客户」填个名字就行，装车第一步立刻就多一个选项。
新客户名下还没有品时，分组里会提示去右上角 + 新增品项。删客户前得先把名下的品删掉或改到别家，
避免出现没人管的历史单据。

**为什么选不到某个日期？**
日期是从入库记录里取的。库存里没有的日期不会出现在选项里，就是为了不让发错批次。
先「入库」把这个批次的货记上，日期才会出现。

**一块拖板能放多少箱？**
一层摆几个是现场写死的（包子 7、烧麦 5），按 1.8 米高倒推最多几层：
肉包 7 个 × 8 层 = 56 箱，烧麦 5 个 × 7 层 = 35 箱。
这只是默认起点，现场码多少就调多少；顶层没码满就用「最上层几个」减，3D 里会留出缺角。
一车几块板由你实际装了几块决定，事先不用估。

**一块拖板能放两个品吗？**
不能，这是故意的。一板混装看不出哪批货在哪，出了问题没法翻账。一个品一板，多板拼一车。

**装车算得准吗？**
按箱规整齐堆码估算，不考虑混装插空和重心。箱规量得越准，结果越靠谱。
档案页里按实测外径填毫米数，3D 和体积都会跟着变。

**能导出 Excel 吗？**
「我的 → 导出发货明细」导出 CSV，Excel 双击就能打开，带收货地、客户、拖板号、
品名、生产日期、箱数、件数、体积。
