# 发货助手

仓库发货用的手机端工具。**按拖板记录**：一块一块录，装完自动汇总箱数、体积、重量和装车方案。

纯网页应用（PWA），不装 App、不进应用商店。手机浏览器打开即用，可添加到主屏幕。

## 能做什么

- **按拖板装车**：一块拖板一张卡片，往上加品项、填箱数，卡片上直接画出堆码示意，多少箱一眼看得出来
- **依次编号**：P1、P2、P3 自动排，删掉中间一块会自动重排
- **发车汇总**：算总拖板数、总箱数、总体积、总重量
- **库存流水**：入库、发车、退货、盘点都记成流水，结存由流水实时算出来，随时能查账
- **撤销发车**：发错了撤回，库存按原批次回补，单据退回未发车可以改完再发
- **发车核对**：库存不够会拦住你，告诉你差多少件
- **发货单**：单号自动生成，可导出 CSV（Excel 直接打开）
- **装车方案**：按箱规和车厢尺寸算体积/重量利用率、要不要分车、第一层怎么铺

## 库存是怎么算的

**不存“当前库存”这个数字，只存流水。** 每一笔入库、发车、退货、盘点都记一条带正负号的流水，
结存 = 所有流水相加。这样任何一个环节变动，库存会自动跟着变，不会出现两处数字对不上。

| 动作 | 记成什么流水 | 库存变化 |
|---|---|---|
| 入库 | `+件数` | 增加 |
| 发车 | `-件数`，按批次先进先出拆开记 | 减少 |
| 退货 | `+件数`，回到原批次 | 增加 |
| 盘点 | `(实盘 - 账面)`，正负都可能 | 校正 |
| 撤销发车 | 把当初的出库逐条反向记回 | 还原 |

「库存」页点开任意品项，能看到结存、每个批次剩多少、以及最近 6 条流水，账是怎么来的全在这儿。

库存在发车时如果不够，不会强行拦住（仓库常有先发货后补单的情况），但会：
1. 发车前弹窗告你差多少件，让你确认；
2. 缺口记成一笔“超发”流水，账面显示负数，红字标出来；
3. 事后用入库或盘点把它平掉，流水里能看到这两笔是抵平的。

## 一次完整的发货流程

1. 「装板」→ 新建车次，填客户名
2. 「加一块拖板」→ 选品项 → 填这块拖板上放了几箱
3. 重复第 2 步，直到所有拖板录完
4. 「确认发车」→ 自动汇总，同时扣减库存
5. 「装车」→ 看这车装不装得下、要不要分车

## 本地运行

```bash
npm install
npm run dev
```

浏览器打开终端提示的地址（通常是 http://localhost:5173）。

## 部署到 GitHub Pages（获取一个固定网址）

### 1. 在 GitHub 上新建仓库

打开 https://github.com/new ，仓库名随便填（例如 `ship-helper`），
**必须选 Public**，不要勾选任何初始化文件，点 Create repository。

### 2. 把代码推上去

在本目录下执行（把 `你的用户名` 和 `ship-helper` 换成你的）：

```bash
git branch -M main
git remote add origin https://github.com/你的用户名/ship-helper.git
git push -u origin main
```

### 3. 打开 Pages

仓库页 → **Settings** → 左侧 **Pages** → 找到 **Build and deployment**，
把 **Source** 改成 **GitHub Actions**。

### 4. 等自动构建

仓库页 → **Actions** 标签，会看到 `Deploy to GitHub Pages` 正在跑，等它变绿（约 1 分钟）。

### 5. 拿到网址

地址是：

```
https://你的用户名.github.io/ship-helper/
```

这个地址**永久不变**。以后改了功能，只要 push 一次，刷新就是新版，网址和二维码都不用换。

### 6. 生成二维码

打开 App 的「我的」页面，二维码已经生成好了，截图保存或直接打印，贴在仓库门口和工位上。

## 手机上用起来像 App

- **安卓 Chrome**：打开网址 → 右上角菜单 → 添加到主屏幕
- **iPhone Safari**：打开网址 → 底部分享按钮 → 添加到主屏幕

添加后从桌面图标进入，是全屏的，没有浏览器地址栏。

## 数据说明

**数据存在你自己的手机浏览器里（IndexedDB 浏览器数据库），不会上传到任何服务器。**

- 你和同事各自扫码打开，是各自独立的一份数据，互相看不到，也不会实时同步
- 换手机、清缓存、换浏览器都会读不到旧数据
- 重要数据请定期在「我的 → 导出备份」存一份 JSON

**如果两个人要同时录同一车货，这个版本不能用**——两个人各算各的，库存一定会对不上。
需要多人共享时，要额外接一个云数据库，界面不用改。

### 能存多少条

一车 8 块拖板约 1.3 KB（含品项、箱数、时间），实际占用按手机剩余空间分配：

| 记录量 | 占用 | 说明 |
|---|---|---|
| 100 车 | 约 130 KB | 一个月都用不到 |
| 1,000 车 | 约 1.3 MB | 一年多的量 |
| 10,000 车 | 约 13 MB | 十年量，手机照样无压力 |

早期版本用的是 localStorage（上限 5 MB，约 2,000 车就满），现在换成 IndexedDB，
上限变成手机剩余空间的一部分（通常几百 MB 起），并且启动时会自动把老数据搬过去。

「我的 → 容量」可以看到实时占用、已记车次，以及按剩余空间还能记多少车。
写入失败时页面顶部会直接弹红条提示，不会再出现「显示成功但其实没存下来」的情况。

## 常见问题

**拖板上的箱数怎么改？**
点那块拖板卡片，用加减号调，或者在品项上加。加到 0 就自动移除了。

**装车算得准吗？**
按「同类箱规整层堆码」估算，不考虑混装插空和重心。超重优先于超体积，最终以现场为准。
箱规量得越准，结果越靠谱。装车页右上角可以改车厢尺寸。

**一块拖板能放多少箱？**
软件不限制，按你实际装的录。图上每行显示 6 箱，箱数多时格子会自动压扁，仍然能看出比例。

**能导出 Excel 吗？**
「我的 → 导出发货明细」导出 CSV，Excel 双击就能打开，带拖板号、品名、箱数、件数、体积、重量。
