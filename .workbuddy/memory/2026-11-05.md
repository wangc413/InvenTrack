## 同日：存储层从 localStorage 换成 IndexedDB

用户担心"浏览器内存够记多少条"。实测一车 8 块拖板 ≈ 1254 字符 ≈ 1.3 KB，
localStorage 5MB（UTF-16 计入）约 2000 车就满，且原 `commit()` 用空 catch **静默吞掉写入失败**，
这是真正危险的地方（界面显示成功但没存下）。

**改造**（`src/lib/store.ts`）：
- 主存储 IndexedDB（`inventrack` / store `kv` / key `db`），结构化克隆存对象；
  启动 `initStore()` 时把旧 localStorage 快照迁过去并 `removeItem` 避免双份配额
- 打开失败（隐私模式等）自动退回 localStorage，`info.mode` 记录当前模式
- 同步 API 不变（`commit` 先改内存再 debounce 120ms 落盘），`pagehide` / `visibilitychange` 时 `flush()`
- 写失败不再静默：`StorageInfo.error` → App.tsx 顶部红条
- 启动时调 `navigator.storage.persist()` 申请长期保留
- `main.tsx` 改为 `initStore()` 完成后才 render，index.html 加 `#root` 内启动占位
- 新页面：Me.tsx「容量」卡（已用 KB / `navigator.storage.estimate` 上限 / 进度条 / 车次-拖板-品项统计）
- Load.tsx 单据条只渲染「未发车 + 最近 15 单」，避免上千按钮
- 用 fake-indexeddb + esbuild 跑过 11 项临时测试（迁移/落盘/FIFO 扣减）后已删除

**数据规模结论**：100 车 ≈130KB，1,000 车 ≈1.3MB，10,000 车 ≈13MB，IndexedDB 上限按手机剩余空间算。
## 同日：库存板块改为流水账（ledger）

用户问"库存要一直更新计算、牵一发动全身，能做到吗"。答案是能，但**不能把库存当数字存**。

**模型改造**（`src/lib/store.ts`）：
- 新增 `Move{ id, at, type: in|out|return|adjust, skuId, batchId, qty(带符号), ref, note, voided? }`
- `DB.moves: Move[]` 成为库存唯一真相；`Batch` 删掉 `left` 字段，只留入库总量 `qty`
- `project(db)` 一次性把全部流水累加成 bySku / byBatch 两个 Map，按 DB 对象引用缓存
- `stockOf` / `batchLeft` / `batchesOf`（返回 `{batch,left}[]`）/ `movesOf` / `todayFlow` 全改为派生
- `shipOrder` 不再改数字，而是按 FIFO 给被吃到的批次各记一笔负数流水；不够时追加一条 `batchId:''` 的超发流水把缺口显性化
- `unshipOrder`：把该单出库流水逐条反向记为 `return`，单据退回 `draft`；用 `voided` 标记原流水，防止"发→撤→再发→再撤"重复回补
- `addBatch` / `returnToBatch` / `adjustBatch` / `removeBatch` 均以流水为准
- `shortages(db, order)` 供发车前核对

**迁移**：老数据用 `入库总量 qty` + `-(qty-left)` 两条流水还原历史；`left > qty` 时补一条盘盈 adjust。

**界面**：
- Stock.tsx 重写：结存/箱数 + 批次列表（含 退货/盘点 按钮）+ 最近 6 条流水 + 入库按钮；表头显示今日入/出
- Pallets.tsx 发车前 `shortages` 弹窗告警，允许超发但显式说明
- Load.tsx 已发车单加「撤销发车 · 库存回补」
- Me.tsx 新增「导出库存流水 CSV」（含正负数量、单据号、说明）

**验证**：fake-indexeddb + esbuild 临时测试 19 项全过（迁移保余量、FIFO、撤销、盘点、退货、超发、反复撤销幂等、落盘一致），测完删除临时文件与依赖。

但物理上这块板超标了。用户给定「每层 6 个」的假设，暂不擅改。

## 11-06 库存改用「箱」为单位（显示与录入），账本内部仍是件

**决策**：不把账本改存箱。件是跟客户对账的最小单位，改存箱就丢了拆零能力，老数据也要做
除不尽的迁移。做法是在**边界换算**：界面输入箱数 → ×每箱件数 → 记账仍记件；显示时再拆回箱。

`src/lib/calc.ts` 新增三个小函数：
- `splitBoxes(qty, perBox)` → `{ boxes, tail }`，按绝对值拆，符号另外看
- `boxText(qty, perBox)` → 「42 箱」「41 箱 + 3 件」
- `moveText(qty, perBox)` → 「+42 箱」「−6 箱」「+10 箱 3 件」（流水行要带符号，
  且第二个数字不加「+」，否则一行里出现两个加号很乱）

`src/lib/store.ts`：
- `todayFlow()` 从「件」改成「箱」，按每个品项自己的 `perBox` 折算，保留一位小数。
  顺手修了一个老 bug：原来没跳过 `voided`，撤销发车后当日「出」仍把已作废的出库算进去，
  现在跳过，入/出都干净了。返回字段 `inQty/outQty` → `inBoxes/outBoxes`。

`src/pages/Stock.tsx` 基本重写：
- 列表主数字 = 整箱数，下面小字 `箱 · 456 件`；有零头时 `箱 + 3 件`
- 表头 `结存 117 箱 + 3 件 · 今日 入 118.4 / 出 1 箱`（有零头才显示小数）
- 批次行 `14 箱`、`生产 11-02 · 入库 15 箱`；流水行 `+10 箱 3 件`
- 三个弹层（入库/退货/盘点）统一两个输入框：**箱数 + 零头件**，零头留空即整箱
- 盘点预填按余量拆成 箱 + 零头
- 底部提示补一句「零头件单独填在右边那一格」

**踩到的排版问题**：流水行是 `76px 34px 60px 1fr` 的 grid，`+10 箱 3 件` 在 60px 里折成两行。
改成 `76px 34px auto 1fr`，并给 `.flow-qty` 加 `white-space: nowrap`。

另外把装车页残留的「件」也统一了：选品列表的结存、该日期剩余、超发提示、3D 合计、发车确认弹窗，
档案页 `存 57 箱`、`每箱 8 件`。

**验证**（CDP 无头，390×844）：入库 10 箱 + 3 件 → 67 箱 + 3 件（57 箱 456 件 + 83 件 = 539 = 67×8+3），
结存 118 箱 + 3 件，今日入 118.4；盘点 15 → 14 箱，流水 −1 箱，今日出 1 箱，头部同步到 117 箱 + 3 件。

## 11-06 盒马示例库存统一 200 箱/日期 + 库存不足改成硬拦截

**需求**：盒马每个品的每个日期都 200 箱；发车时箱数超过库存要报错「库存不足」。

### 示例库存
- `HM_STOCK_DAYS = [9, 6, 3, 1]`、`HM_STOCK_BOXES = 200`，seed 里遍历盒马三个品 × 四个日期，
  每次 `stock(sku, daysAgo(n), 200 * perBox)`。快乐猴/菜洋洋保持小库存，方便试拦截。
- **老数据怎么补**：给 DB 加 `version`（`DATA_VERSION = 2`），`migrate()` 里当 `version < 2` 时
  按「每个盒马品 × 每个日期补齐到 200 箱」只补差额，补成一笔 `in` 流水（ref=示例补齐）。
  不动已有单据、不删批次。已发货扣掉的量不会再补回来（补的是差额，不是重置）。
- **必须把迁移结果立刻落盘**，否则每次启动都会再补一遍 → 库存翻倍。IDB 分支迁移后
  `await idbSet(IDB_KEY, state)`；localStorage 分支 `setItem(KEY, ...)`。
  实测：构造 version=1、盒马只剩 1 个批次 50 箱的老数据 → 加载后变成 4×200 箱，再刷新仍是 800，不重复补。

### 库存不足拦截（原来是「提醒但放行」）
- 装车页（`NewOrderForm`）：新增 `takenBoxes`（同车同品同日期的已占箱数）和
  `avail = leftBoxes - takenBoxes`；`boxes > avail` 时第三个格子显示负数并变红，
  红色 `.alert` 写明「还能装 X 箱（本车已占 Y 箱），请减少 Z 箱」，「加入订单」`disabled`。
- 编辑拖板（`PalletSheet`）：同样算 `takenBoxes`（排除正在编辑的这块），超了禁用「保存」。
- 发车（`confirmShip`）：原来是 `confirm` 让用户确认超发，现在直接 `alert` 拦住并 return，
  单据留在草稿状态。`shipOrder` 里的超发兜底逻辑保留，只作为老草稿的防线。
- 顺带把「箱数超过满板」的提示在超库存时隐藏，免得两条提示挤在一起。

**验证**：200 箱→可用 5 块板；填 260 → 显示 −60 红字 + 提示 + 按钮灰；同品同日再加 10 箱
（本车已占 200）→ 提示「还能装 0 箱」并禁用；建车 200 箱后把该日期盘点成 100 箱 → 发车被拦，
装车页仍是 5 块板、记录页 0 条。

## 11-06 装车流程大改：从「填箱数自动折板」改成「3D 工作台逐板码」

**用户要的**：库里拉出来的一板有多少件、总共几板都不确定，不能再预设一板 42 箱。
建完车次直接出 3D，选品就摆到第一块板上，层数 / 顶层数要能随手调，
点「上车」之后自动跳到下一块空板。

### 数据与计算
- 新增 `maxPerLayer(sku)` / `maxLayers(sku)`（`src/lib/calc.ts`）：
  按标准托盘 **1200×1000** 和总高 **1.8 m** 反推这一层最多码几个、最多几层。
  烧麦 465×410 一层其实只能放 **4** 个（以前固定 6 个是超托盘宽度的，`stackLayout` 也不管托盘尺寸）；
  肉包 500×335 是 6 个 —— 正好和之前「每层 6 个」的假设吻合。
- 删掉 `store.addPalletsByBoxes()`。它就是把箱数折成 42 箱一块的逻辑，新流程用不到。
- `Sku` 加可选 `nick`（列表短称），`nickOf(sku)` 按箱面大字推：鲜汁大肉包 → 肉包。
  装板页的品类标签太窄，5–7 个字必换行，短称是必要的。SkuForm 暂时不填，自动推。

### 3D 引擎（`src/lib/box3d.ts` 重写挂载方式）
- `SceneHandle` 从 `{dispose, resetView}` 变成 `{setPallets, resetView, dispose}`。
  **renderer / 相机 / 灯光 / 纹理只建一次**，改层数只清空 `root` 重排箱子。
  之前每次改层数都要重建整个 WebGL 场景 + 重画 canvas 纹理，拖 Stepper 会一卡一卡。
- 纹理与几何按 `sku.id` 缓存在闭包里，跨次重排复用；托盘几何是每次新建的，
  记在 `transient` 数组里，重排前先 dispose，否则会漏。
- 取景从「包围球 + FOV」改成「**包围盒尺寸 + FOV**」：
  横向取 `max(size.x, size.z)`、纵向取 `size.y`，各自除以对应的 tan(fov/2)，再乘 1.16 留白。
  包围球会把深度也算进去，竖长的垛（9 层烧麦 1.79 m 高、0.93 m 宽）会被压得很小。
- 新增 `emptyPallet` 选项：没选品时画一块空托盘，而不是一片空白。
- `camDir` 每帧跟着 `controls` 记，重排时按当前视角重新取景 —— 用户转过的角度不会被拽回去。

### 装板工作台（`PackingBoard`）
- **上 3D 下控件**：`.page.pack-page` 改成 `overflow:hidden` 的 flex 列，3D 固定
  `clamp(180px, 30vh, 280px)`，下面 `.pack-panel` 自己滚。调层数时画面一直在。
- 选品用 chips（带色点），选中立刻按该箱规算默认层数/每层数，**不是拍一个 42**。
- 三个 Stepper：层数 / 每层几个 / 最上层几个。层数上限放到 24（超 1.8 m 只在 HUD 变红提醒），
  每层上限锁死在 `maxPerLayer`（托盘就那么大，塞不下就是悬空）。
- 箱数/件数不再单列一排格子，合并进 3D 左下角的 HUD：
  第一行 `烧麦 28 箱 1008 件`，第二行 `这天还能装 200 箱`，超高时第二行变红。
  这样一屏能塞下 3D + 两张卡 + 三行控件，不用滚。
- `重置视角` 挪到 3D 右上角，底部让给 HUD。
- 「装上 P1 · 接着装 P2」→ `addPallet` 后清空选品，HUD 回到「还没选品」、托盘变空，
  标题自动变 P2（`order.pallets.length + 1` 派生）。这就是「自动跳到下一板」。
- 装车页的「改层数」改成「重码」，复用同一个工作台（`packing = { editId }`），
  保存后回列表；编辑时 `taken` 要排除自己那块。

### 布局踩的坑
- 3D 40vh + 两张长卡 + 一排汇总格子 = 一屏放不下，层数控件被 dock 按钮压住。
  依次砍：日期 chip 去掉库存数字（省一行）、汇总格子并进 HUD（省 70px）、
  3D 从 40vh 降到 30vh、「每层最多 N 个」挪到行内小字。
  360–390px 宽、844 高下三行控件刚好在一屏；667px 小屏仍需滚一次，可接受。
- `.pack-hud` 一开始和 `.box3d-hint`（左下角「拖动旋转」）打架，装板页里直接隐藏 hint。

### 验证（CDP 无头 390×844）
烧麦：默认 7 层 × 4 个 = 28 箱 → 减到 5 层 20 箱 → 每层改 3 变 15 箱、顶层自动跟到 3
→ 装上 P1 → 标题变 P2、HUD 回「还没选品」；肉包：默认 8 层 × 6 = 48 箱，
减两层 36 箱；列表 P1 28 箱 7 层×4、P2 36 箱 6 层×6；发车后整车 3D 三块板颜色/层数都对。
9 层烧麦（2.26 m）→ HUD 第二行红字「超过 1.8 m 上限」，3D 仍完整不裁切。
同品同日期码第二块时，HUD 显示「这天还能装 172 箱」（200 − 28）。

## 一层码法写死（同日晚）

现场给了真实数据，不再让程序算「最多能摆几个」：

- 托盘规格 **1200 × 1000 mm**（`PALLET_L / PALLET_W` 本来就是这个值，这次在文档和 UI 里写明）。
- **包子类（菜包 / 肉包）一层固定 7 个 = 3 竖 + 4 横**，4 个横的挤成 2×2。
  竖 = 箱长（500）顺 1.2 m 边、3 个沿 1 m 边排开（肉包 3×335=1005，挤一挤齐板）；
  横 = 转 90°（335 顺 1.2 m），2×2 占 670×1000。合起来 1.2 m 上 500+670=1170，剩 30 mm 下手。
- 烧麦 465×410 还是方阵 2×2 = 4 个；其它品回落到按箱规铺方阵。
- 实现：`calc.ts` 新增 `Slot` / `LayerPlan` / `layerPlan(sku)`（`/菜包|肉包/` 走 `baoPlan`，否则 `gridPlan`），
  `perLayerOf` 取代 `maxPerLayer` 的实际逻辑，删掉 `stackLayout`。
- `box3d.ts`：托盘固定画 1.2×1.0（不再按箱垛缩），箱子照 `slots` 摆，`turn` 的转 `rotation.y = π/2`；
  一层几个到底由 `plan.perLayer` 决定，`perLayer` 只做 clamp。
- `Load.tsx`：「每层几个」从 Stepper 改成只读，行内小字给码法（`3 竖 + 4 横（2×2）`），
  只剩 码几层 / 最上层几个 可调；建档页每个品也加了一行「一层 7 个 · 3 竖 + 4 横（2×2）」。

### 取景同时修掉的老问题
8 层肉包（1.66 m）在 252px 高的舞台上被切掉底部——原来的 `dist = 高度/2 ÷ tan(fov/2)` 只算了正面高度，
斜着看时堆高和进深会叠加投影。改成按包围盒 8 个角投影到相机基（right / up / camDir）求所需距离，
取 max × 1.1，托盘和整垛都能完整进画面。

### 验证（CDP 无头 390×844，每次换干净 profile 让示例数据重播）
肉包 1 层 = 7 箱、8 层默认 56 箱；菜包 1 层 7 箱、8 层顶层 3 个 = 52 箱；烧麦 1 层 4 箱、默认 7 层 28 箱。
装上 P1→P2 自动跳板；列表 P1 肉包 56 箱（8 层×7）、P2 菜包 52 箱（8 层×7·顶层 3）；
重码 P1 改 6 层保存 → 42 箱，合计 94 箱；发车后整车 3D 两块板高度差、顶层缺角都对。

## 隔层调头 + 装板页改版（当晚）

用户补充了关键现场细节：一层摆法固定，但**第二层要整体调头**（稳固性），并且烧麦是**一层 5 个**。

- `calc.ts` 新增 `layerSlots(plan, layer)`：单数层整体 180°（x、z 取反，`turn` 不变）。
  为什么是 180° 而不是 90°：7 个的码法转 90° 后 1.2 m 那边要 500+670=1170 变成进深，1 m 那边放不下；
  180° 只是把「3 竖那一列」和「2×2 方块」左右对调，尺寸不变，缝正好错开。
- 烧麦 `shaomaiPlan`：后排 3 个（410 顺 1.2 m，3×410=1230 两边各挤 15 mm）+ 前排 2 个（465 顺 1.2 m），
  进深 465+410=875。跟用户手绘图一致（上排 3 个竖、下排 2 个横，中间留缝）。
- `box3d.ts`：每层现取 `layerSlots(plan, layer)` 摆箱；取景 padding 1.1 → 1.16。

### 界面
- 装板页重做：只留「返回/板号」顶栏 + 品/日期两个下拉 + 满屏 3D + 底部悬浮操作卡片，
  面板卡片全部删掉（`pack-panel / pack-row / pack-note / pack-cap / pack-fixed` 一并清理）。
- 卡片结构：表头（品名 · 箱数 · 件数 ｜ 这天还能装 N 箱 / 红字告警）→ 码几层 −/+、顶层几个 −/+、每层 7 →
  底部小字「3 竖 + 4 横（2×2）· 隔层调头」。
- 布局踩坑：`.page` 原本 padding 0 导致 3D 舞台被 dock 压住 → `padding-bottom: calc(118px + safe-area)`；
  操作卡 124px 高 → `.pack-stage.with-ops .box3d { inset: 0 0 136px 0 }`，画布不再被卡片盖住。
- 下拉：`.pack-pick` 两个 pill（品 / 日期），点开 `.picker-pop` 覆盖在 3D 上，日期项带「200 箱」余量；
  `.picker-mask` 点空白收起；选完自动收起。

### 验证（CDP 无头）
390×844：肉包 8 层 56 箱、2 层 14 箱（上下层方向明显错开）、烧麦 1 层 5 箱 / 2 层 10 箱、装上 P1 自动跳 P2 空板。

## 烧麦前排留缝

用户确认「烧麦的两个之间留缝」。`shaomaiPlan` 里前排 2 个从「居中贴齐」改成「贴两侧、中间留缝」：
缝宽 = 3×410 − 2×465 = **300 mm**，即前排两个的外沿跟后排 3 个的外沿对齐（±615），
前排箱心 x = ±382.5，内沿 ±150。实现是 `gap = max(0, 3*w - 2*l)`、`stepX = l + gap`，
所以换箱规也不会算出负缝；`note` 改成「3 竖 + 2 横（留缝）」，卡片底部那行跟着变。
