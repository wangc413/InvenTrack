## 同日：存储层从 localStorage 换成 IndexedDB

用户担心"浏览器内存够记多少条"。实测一车 8 块拖板 ≈ 1254 字符 ≈ 1.3 KB，
localStorage 5MB（UTF-16 计入）约 2000 车就满，且原 `commit()` 用空 catch **静默吞掉写入失败**，
这是真正危险的地方（界面显示成功但没存下）。

**改造**（`src/lib/store.ts`）：
- 主存储 IndexedDB（`inventrack` / store `kv` / key `db`），结构化克隆存对象；
  启动 `initStore()` 时把旧 localStorage 快照迁过去并 `removeItem` 避免双份配额
- 打开失败（隐私模式等）自动退回 localStorage，`info.mode` 记录当前模式
- 同步 API 不变（`commit` 先改内存再 debounce 120ms 落盘），`pagehide` / `visibilitychange` 时 `flush()`
- 写失败不再静默：`StorageInfo.error` → App.tsx 顶部红条
- 启动时调 `navigator.storage.persist()` 申请长期保留
- `main.tsx` 改为 `initStore()` 完成后才 render，index.html 加 `#root` 内启动占位
- 新页面：Me.tsx「容量」卡（已用 KB / `navigator.storage.estimate` 上限 / 进度条 / 车次-拖板-品项统计）
- Load.tsx 单据条只渲染「未发车 + 最近 15 单」，避免上千按钮
- 用 fake-indexeddb + esbuild 跑过 11 项临时测试（迁移/落盘/FIFO 扣减）后已删除

**数据规模结论**：100 车 ≈130KB，1,000 车 ≈1.3MB，10,000 车 ≈13MB，IndexedDB 上限按手机剩余空间算。
## 同日：库存板块改为流水账（ledger）

用户问"库存要一直更新计算、牵一发动全身，能做到吗"。答案是能，但**不能把库存当数字存**。

**模型改造**（`src/lib/store.ts`）：
- 新增 `Move{ id, at, type: in|out|return|adjust, skuId, batchId, qty(带符号), ref, note, voided? }`
- `DB.moves: Move[]` 成为库存唯一真相；`Batch` 删掉 `left` 字段，只留入库总量 `qty`
- `project(db)` 一次性把全部流水累加成 bySku / byBatch 两个 Map，按 DB 对象引用缓存
- `stockOf` / `batchLeft` / `batchesOf`（返回 `{batch,left}[]`）/ `movesOf` / `todayFlow` 全改为派生
- `shipOrder` 不再改数字，而是按 FIFO 给被吃到的批次各记一笔负数流水；不够时追加一条 `batchId:''` 的超发流水把缺口显性化
- `unshipOrder`：把该单出库流水逐条反向记为 `return`，单据退回 `draft`；用 `voided` 标记原流水，防止"发→撤→再发→再撤"重复回补
- `addBatch` / `returnToBatch` / `adjustBatch` / `removeBatch` 均以流水为准
- `shortages(db, order)` 供发车前核对

**迁移**：老数据用 `入库总量 qty` + `-(qty-left)` 两条流水还原历史；`left > qty` 时补一条盘盈 adjust。

**界面**：
- Stock.tsx 重写：结存/箱数 + 批次列表（含 退货/盘点 按钮）+ 最近 6 条流水 + 入库按钮；表头显示今日入/出
- Pallets.tsx 发车前 `shortages` 弹窗告警，允许超发但显式说明
- Load.tsx 已发车单加「撤销发车 · 库存回补」
- Me.tsx 新增「导出库存流水 CSV」（含正负数量、单据号、说明）

**验证**：fake-indexeddb + esbuild 临时测试 19 项全过（迁移保余量、FIFO、撤销、盘点、退货、超发、反复撤销幂等、落盘一致），测完删除临时文件与依赖。
